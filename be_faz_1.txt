# Staff .NET Yol Haritası

## Summary

Amaç: feature öğrenen geliştiriciden üretim sistemleri tasarlayan ve yön veren geliştiriciye çıkmak.

Önerilen ilerleme:
1. Temeli sağlamlaştır
2. Gerçek backend akışlarını kur
3. Operasyonel ve dağıtık sistem konularına geç
4. Mimari karar verme ve teknik liderlik kasını geliştir

Başarı kriteri:
- Her konuyu sadece okuyup geçmemek
- Her başlık için küçük ama çalışan bir proje çıkarmak
- Her projede test, logging ve production concern eklemek

## Roadmap

### 1. Baslangic Seviyesi

Hedef: .NET web uygulamasının temel yapı taşlarını refleks haline getirmek.

Başlamadan önce derin temeller

### 🔹 Dil & Temel Yapılar

* async / await (derin)
* Exception handling (doğru kullanım)
* Generics (temel + constraints)
* Nullable reference types

### 🔹 Collections & LINQ

* IEnumerable vs IQueryable
* Deferred execution
* LINQ optimizasyonu

### 🔹 OOP & Clean Code

* SOLID (özellikle SRP, DIP)
* Interface vs abstraction
* Composition vs inheritance
* Immutability (özellikle records ile)

### 🔹 Delegates & Functional Basics

* Func / Action
* Lambda expressions
* Extension methods

## 🥈 Tier 2 — ÇOK ÖNEMLİ (Mid → Senior geçiş)

> Seni diğerlerinden ayıran kısım burası.

### 🔹 Concurrency & Async Internals

* Task vs Thread

### 🔹 Performance Awareness

* Garbage Collection (temel mantık)
* IDisposable & using
* Boxing / Unboxing

### 🔹 Advanced Generics

* Generic constraints
* Covariance / Contravariance

### 🔹 Exception Design

* Custom exception
* Exception vs Result pattern

### 🔹 Collections Deep Dive

* Dictionary vs List vs HashSet
* Big-O basics
* Concurrent collections

## 🥉 Tier 3 — İYİ BİL (Senior polish)

> Senior seviyede “bu adam biliyor” dedirten şeyler.

### 🔹 Language Deep Features

### 🔹 Reflection & Attributes

* Reflection kullanımı
* Custom attribute yazma

### 🔹 Parallel Programming

* Parallel.For
* PLINQ

### 🔹 Testability

* Pure functions
* Side-effect kontrolü

## 🧪 Tier 4 — NICE TO HAVE (Niş ama güçlü)

> Her gün lazım değil ama doğru yerde çok fark yaratır.

* Span<T> / Memory<T>

### 🔹 Low-level Control

Hedef: sadece kod yazan değil, doğru sistemi ve doğru trade-off’u seçen mühendis olmak.

Konular:
- Monolith vs microservice kararları
- Build vs buy kararları
- Domain modeling
- Bounded context
- Observability strategy
- Security by design
- Cost/performance trade-off
- Backward compatibility
- Technical roadmap oluşturma
- Code review ve engineering standards
- Mentoring ve bilgi yayma
- Incident analysis / postmortem yaklaşımı

Bu aşamada çalışılacak pratikler:
- bir sistemi ADR ile tasarlamak
- production readiness checklist hazırlamak
- bir PR template ve coding guideline yazmak
- bottleneck analizi yapmak
- bir sistemi sadeleştirme refactor’ü planlamak
